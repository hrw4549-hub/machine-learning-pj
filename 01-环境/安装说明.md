# 第七题：通用安装说明

适用：Windows 11、x86_64、WSL2、Ubuntu 22.04、Python 3.10。建议至少 16GB 内存、30GB 可用空间，使用支持 WSL 的 NVIDIA 显卡与 Windows 驱动。

本压缩包内的 pj7-environment 文件夹包含安装脚本、固定依赖、ACT 官方源码和验收脚本。**这是联网安装包**，系统包、Python、PyTorch 等仍需下载。

## 1. 准备目录

将 PJ7-安装与交接.zip 解压到自己的项目文件夹，例如 E:\course-project，应得到：

```text
E:\course-project\pj7-environment\README.md
E:\course-project\pj7-environment\Install-Windows.ps1
```

在解压后的 pj7-environment 文件夹打开 PowerShell，不要在压缩包预览窗口内运行脚本。不要把文件散放到盘符根目录。

## 2. 安装 WSL

已有可用 WSL2 时跳到第 3 步，否则运行：

```powershell
cd 'E:\course-project\pj7-environment'
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Install-Windows.ps1
```

将 `E:\course-project\pj7-environment` 换成你实际解压后的脚本文件夹路径；路径有空格也保留引号。
`cd` 用来进入该文件夹，命令中的 `.\` 表示当前文件夹。

按提示同意 UAC。脚本需要管理员权限启用组件，不自动重启；看到 reboot-required 后保存工作并手动重启。
隐藏安装窗口的进度在 logs\windows-status.json。
若提示虚拟化不可用，先在 BIOS/UEFI 开启虚拟化；若 Windows 报组件损坏，先修复系统再继续。

## 3. 安装 Ubuntu

重启后重新打开上述目录的 PowerShell：

```powershell
cd 'E:\course-project\pj7-environment'
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Install-UbuntuDistribution.ps1
wsl -d Ubuntu-22.04 --cd ~
```

默认虚拟磁盘位于项目目录的 .wsl\Ubuntu-22.04，例如 E:\course-project\.wsl\Ubuntu-22.04。
首次启动创建自己的 Linux 普通用户与密码；密码输入不显示字符属于正常现象。
已有同名 Ubuntu 会被沿用，如果它属于其他项目，先确认是否适合复用；不要删除或注销别人的发行版。

## 4. 安装项目环境

以下命令在 **Ubuntu 终端** 运行，盘符和目录按实际位置修改：

```bash
cd '/mnt/e/course-project/pj7-environment'
bash Install-Ubuntu.sh
source ~/pj7/activate.sh
```

系统依赖阶段输入自己的 Linux 密码。脚本使用 ~/pj7/.conda 独立环境，代码在 ~/pj7/src/act，均存储在 Ubuntu 虚拟磁盘内。
不要混装 ACT 旧 README 指定的另一套 MuJoCo / dm-control 版本。
Ubuntu 内不需要额外安装 NVIDIA 显示驱动或完整 CUDA Toolkit。

基线：Python 3.10，PyTorch 2.5.1+cu121，torchvision 0.20.1+cu121，MuJoCo 3.2.7，robosuite 1.5.1，NumPy 1.26.4。
完整 pip 版本在 requirements-linux.lock.txt，ACT 固定提交为 742c753c0d4a5d87076c8f69e5628c79a8cc5488。

## 5. 实际验收

仍在 Ubuntu 的脚本目录内运行：

```bash
bash Verify-Ubuntu.sh
```

命令须正常结束，下列两个文件的 passed 均为 true：

- logs/verification-egl/report.json：CUDA 运算、Lift 双相机、两次重置和动作执行。
- logs/verification-act.json：ACT 的 GPU 前向、反向传播、一次更新和推理。

检查 logs/verification-egl/ 的 PNG 能看到仿真场景。包内 verified-example/ 是原机器结果，不能代替新机器验收。

EGL 不可用时可尝试：

```bash
PJ7_GL=osmesa bash Verify-Ubuntu.sh
```

没有 NVIDIA GPU 时，仅检查 CPU 仿真：

```bash
source ~/pj7/activate.sh
python verify_environment.py --gl osmesa --allow-cpu --output logs/verification-cpu
```

CPU 仿真通过不代表 ACT GPU 训练验收通过。其他显卡、驱动与 Windows 版本以本机实际验收为准。

## 6. 日常启动与示例

Windows PowerShell：

```powershell
wsl -d Ubuntu-22.04 --cd ~
```

Ubuntu：

```bash
source ~/pj7/activate.sh
cd ~/pj7
```

运行 Lift 后台仿真实例，将路径换成自己的解压目录：

```bash
cd '/mnt/e/course-project/pj7-environment'
python verify_environment.py --gl egl --output logs/my-first-lift
```

图片在 logs/my-first-lift/，不会自动弹出动画窗口。此例执行随机动作，不演示已训练好的抓取策略。

## 7. 问题反馈

提供报错末尾、新机器显卡/驱动信息、logs/ubuntu-install.log 和最新验收 JSON。
失败后先定位问题再重试，不要反复卸载整个 Ubuntu。
盘符挂载问题参考安装包 README 的兼容处理，通常电脑无需修改挂载。
