## 4. 下一阶段工作顺序

### A. 固定任务与数据定义

确定 Panda Lift 控制器、相机、分辨率、控制频率和成功标准。
本次验收使用 128×128 双相机、20Hz、7 维动作，这些是验收配置，不是已确定的训练参数。
核实动作分量含义、归一化范围、夹爪方向及状态维度，不要把官方 ACT 的 14 维输入输出直接套到 Panda。

### B. 采集并回放示范

选择人工遥操作或验证过的专家控制器，先保存并回放少量成功 Lift 轨迹。
记录图像、状态、动作、时间/频率和任务配置，明确观测与动作的时序对齐。
HDF5 可作为格式选择，但本次尚未提供采集器、数据转换器或最终数据格式约定。

### C. 适配 ACT 并做小规模验证

官方 ACT 示例是双臂传方块和插入，仍需修改状态/动作维度、数据加载、归一化和闭环动作执行。
先验证小数据过拟合、保存/恢复模型、仿真闭环调用，再正式训练。

当前源码为固定提交的 detached HEAD，修改前先在 ~/pj7/src/act 建立开发分支：

```bash
cd ~/pj7/src/act
git switch -c pj7-lift
```

记录开发版本提交。安装脚本会拒绝与基线不同提交的已有源码，不要为了重新安装而丢弃开发修改。

### D. 正式对比实验

回看第七题原始要求确认方案，例如比较 20/50 条示范或动作执行长度。
固定数据划分、随机种子、相机/控制器、测试初态、测试次数和成功标准，保存配置、模型和结果。
随机动作验收不是抓取性能测试，当前报告不能作为课程实验成功率。
Push-T 为选做扩展，robosuite 不自带标准 Push-T，本次未实现。

## 5. 通用安装与交付边界

只需转交 PJ7-安装与交接.zip。接收方解压后先看安装说明.md，在自己的项目文件夹安装并重新验收。
脚本不固定 Windows 盘符和 Linux 用户名，默认 Ubuntu 磁盘位于项目目录内。
这是联网安装包，不含完整系统镜像、全部 wheel、训练数据和模型权重。
requirements-linux.lock.txt 固定 pip 版本；apt 包未做系统快照，不能声称不同日期安装的系统逐字节一致。

## 6. 共享机器与备份

若同学远程使用，需另行配置 SSH / VS Code Remote - SSH，以及局域网或组网访问。
当前没有可以直接分发的远程登录入口。
每人独立账号、代码、输出；示范数据可共享，单张 GPU 排队；用 tmux 保持训练。不要在文档中传个人密码。
训练数据和模型需单独备份，本安装包不能恢复后续训练成果。
整机迁移可停止训练后用 WSL 官方导出/导入另做备份，不要在 Ubuntu 运行期间直接复制活动的 ext4.vhdx。
